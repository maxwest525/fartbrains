# Decisions log

| # | Date | Decision | Rationale |
|---|------|----------|-----------|
| 1 | 2026-09-03 | Restore the real authentication gate; delete `signInAnonymously()` fallback. | The app signed every visitor in anonymously, giving unauthenticated traffic a valid JWT and therefore access to the paid AI edge functions (all of which authorize with `requireUser`). Not sellable, and an open cost/abuse hole. |
| 2 | 2026-09-03 | Anonymous Supabase sessions are treated as signed-out and actively signed out in `useAuth`. | Defence in depth: stale anonymous tokens already in customers' browsers must not resurrect access. |
| 3 | 2026-09-03 | Removed the single-user email allowlist (`src/lib/allowlist.ts`). | It was already a no-op returning `true` for everything; keeping a fake gate around is misleading. Public signup is the product. |
| 4 | 2026-09-03 | App lock (local passcode) moved out of first run into Settings → App lock. | A device passcode prompt before a new customer has seen the product is a conversion killer, and it is not an account credential. |
| 5 | 2026-09-03 | `notes-feed` authenticates the caller and runs as that user instead of using the service-role key with a shared `NOTES_FEED_TOKEN`. | The shared-token design returned every customer's notes, todos and reminders to any holder of one token. Nothing in this repo calls the function, so the only consumer to update is the external desktop poller, which must now send the customer's own access token. |
| 6 | 2026-09-03 | RLS `UPDATE` policies get an explicit `WITH CHECK` matching their `USING`. | `USING` alone permits a customer to reassign `user_id` on a row they own, moving it into another account's brain. |
| 7 | 2026-09-03 | Share links are `/s/<token>` with a 256-bit token; only its SHA-256 is stored. | The idea UUID must never be authorization, and a database dump must not yield working links. The raw token is shown once and cannot be recovered — a lost link is regenerated. |
| 8 | 2026-09-03 | Public share resolution goes through the `resolve-share` edge function calling a SECURITY DEFINER RPC, not through an anonymous RLS policy on `ideas`. | Keeps `public.ideas` closed to anon entirely, returns only the opted-in fields, and gives somewhere to rate-limit. |
| 9 | 2026-09-03 | Unknown, revoked and expired tokens return the same response. | Otherwise the endpoint distinguishes live links from dead ones, which is an enumeration oracle. |
| 10 | 2026-09-03 | Default shared fields: title + note + summary. Extracted source text, AI chats, tags, folder, reminders, related ideas and owner identity are never shareable. | Matches the product promise that sharing one idea reveals nothing else. |
| 11 | 2026-09-03 | Phone/SMS sign-in is hidden behind `VITE_ENABLE_PHONE_AUTH`, default off. | No SMS provider is known to be configured. A sign-in method that silently never delivers a code locks paying customers out. The code path is kept so it can be switched on once SMS is tested end to end. |
| 12 | 2026-09-03 | One shared guard (`_shared/ai-guard.ts`) authenticates, rate limits, caps input and records usage for every paid route. | Per-route ad-hoc checks drift. Centralising it also puts plan entitlements in exactly one place instead of scattered plan-name checks. |
| 13 | 2026-09-03 | Quota is reserved before the work runs; the outcome is filled in afterwards. | A route that crashes or forgets to report still has to count against the allowance, otherwise failures become a free retry loop. |
| 14 | 2026-09-03 | `ai_usage_events` stores metadata only — operation, plan, sizes, cost, success. | Usage analytics must never become a second copy of customers' private notes. |
| 15 | 2026-09-03 | Weighted quotas: deep research 5x, transcription 3x, ask 2x, everything else 1x. | A flat call count prices a 20-minute transcription the same as an auto-tag. |
| 16 | 2026-09-03 | Deleting an idea soft-deletes it (`deleted_at`) with an undo toast; 30-day retention, then `purge_expired_trash()`. | A product whose promise is "capture anything and find it later" cannot put a captured thought one mis-tap from gone. |
| 17 | 2026-09-03 | Trashing an idea revokes its share links via a database trigger, not application code. | A recipient must stop reading the moment the owner deletes, even if the deletion came from a path that forgot to clean up. |
| 18 | 2026-09-03 | Permanent deletion is only reachable from Trash and only behind an explicit confirmation. | Irreversible actions should require the customer to already be looking at the thing they are destroying. |
| 19 | 2026-09-03 | Export runs client-side as the signed-in user rather than through a service-role function. | Row level security then *guarantees* the file can only contain that account's rows; a server-side exporter would rely on getting a `user_id` filter right on every query. |
| 20 | 2026-09-03 | Account deletion requires password re-entry, a session under 15 minutes old, and the typed phrase DELETE. | It is the one irreversible account action; a stolen or long-lived token must not be enough on its own. |
| 21 | 2026-09-03 | `delete-account` deletes each owned table explicitly rather than relying on `ON DELETE CASCADE`. | A missing cascade would silently leave private rows behind after a customer asked for removal. If any table fails, the auth user is kept so the customer can retry rather than being locked out of a half-deleted account. |
| 22 | 2026-09-03 | Prices come from `STRIPE_PRICE_ID_PRO`, never from the client and never hard-coded. | Public pricing is an irreversible decision the owner has not made. Env-driven price ids mean choosing it later is configuration, not a code change — and a client cannot check out on a price we did not intend to sell. |
| 23 | 2026-09-03 | The Stripe webhook is the only writer of billing state; `subscriptions` is read-only to customers via RLS. | Entitlement must never be something the browser can assert. |
| 24 | 2026-09-03 | `billing_events.id` is the Stripe event id and its primary key. | Stripe delivers at least once; the duplicate insert failing *is* the idempotency check, with no extra locking. |
| 25 | 2026-09-03 | `past_due` keeps paid access; cancellation never restricts reading, searching, exporting or account deletion. | Dunning should not lock someone out mid-cycle, and no billing state should ever hold a customer's own notes hostage. |
| 26 | 2026-09-03 | CORS pinned to `ALLOWED_ORIGIN` / `APP_URL` on all 28 edge functions; `*` only as a local/preview fallback. | With `*`, any page on the internet could call these functions using a customer's token. |
| 27 | 2026-09-03 | Analytics take a fixed event name plus an allowlist of enum-shaped properties; everything else is stripped. | A denylist would fail the first time someone adds a property called `title`. In a product made entirely of private notes, the default must be "nothing leaves". |
| 28 | 2026-09-03 | `track()` and the crash reporter are no-ops until a provider is explicitly installed. | Shipping with no analytics beats shipping with a provider nobody has reviewed — React error messages can quote rendered content, i.e. someone's notes. |
| 29 | 2026-09-03 | Onboarding's first step captures the customer's own real thought; no sample or demo data is created. | Writing anything into someone's private brain on their behalf undermines the one promise the product makes. |
| 30 | 2026-09-03 | Onboarding progress is stored locally per account id, not in the database. | It is not worth a network round trip on first paint, and losing it costs one skippable screen. Keying by user id stops two accounts on a shared device inheriting each other's progress. |
| 31 | 2026-09-03 | Onboarding is offered only to an account with no items, and is skippable at every step. | A returning customer, or one who imported first, must never be interrupted by it. |
| 32 | 2026-09-03 | Every list query is bounded to 100 rows, and first-run uses a count-only query. | Lists ran with no limit, so a customer with ten thousand items downloaded all of them — their entire private vault in browser memory — on every mount. |
| 33 | 2026-09-03 | Trigram (GIN) indexes on the four ILIKE search columns, plus partial indexes on the live-row list scopes. | `ILIKE '%term%'` cannot use a btree index; without trigrams every search sequentially scans the customer's transcripts. |
| 34 | 2026-09-03 | A generated `search_vector` column is added now, before anything queries it. | A generated column backfills on creation; adding it later, on a large table, is a much more disruptive migration. |
| 35 | 2026-09-04 | Privacy and terms ship as drafts behind a visible work-in-progress banner rather than not shipping at all. | Settings needs somewhere to link, and an unmarked placeholder policy is itself a misleading claim. The banner comes off when a lawyer signs the text off. |
| 36 | 2026-09-04 | The privacy draft explicitly says provider training practices are unverified, rather than staying silent. | Silence reads as a denial. This is the one claim most likely to be assumed and most costly to get wrong. |
| 37 | 2026-09-04 | Draft pricing: $9/mo, $90/yr, 50 free / 1,000 Pro weighted AI actions. Owner to confirm. | $8–12 is the band comparable second-brain tools sit in. $9 reads deliberate and leaves headroom to reach $12 without re-platforming. Numbers are unvalidated against a real provider bill — `docs/PRICING.md` says to check before publishing. |
| 38 | 2026-09-04 | The free plan is permanent and includes unlimited items, search, sharing, export and deletion. | The product promise collapses if losing a subscription can hold someone's notes hostage. |
| 39 | 2026-09-04 | STT provider and model are environment-driven, defaulting to the Lovable gateway. | The model was hardcoded across three functions and two vendors, so changing it meant editing several files and deploying. Defaulting to the gateway keeps transcription on the key and bill that already exist; `STT_PROVIDER=elevenlabs` switches it. |
| 40 | 2026-09-04 | Shared transcript cache for public media, keyed by platform + the platform's own id. | Transcription is the most expensive operation in the product and two customers saving the same viral reel were paying for it twice. This is the single largest cost reduction available. |
| 41 | 2026-09-04 | The cache has no `user_id` and holds public media only — never voice notes. | Without an owner column it cannot be used to work out who saved what, and a customer's own recording never lands anywhere another account could reach. |
| 42 | 2026-09-04 | Quota is refunded on a cache hit, a captions-only result, or a failure before spend. | Reserving quota up front stops a crash becoming a free retry loop, but charging an AI action for something we never paid a provider for is just wrong — and it makes the free tier meaningfully more generous. |
| 43 | 2026-09-04 | Transcription writes durable job rows even though processing is still synchronous. | The record is what makes retry, polling and diagnosis possible later; adding the table now avoids a second migration when the worker lands. |
